# 月报 Demo 使用说明

## 启动与演示

在项目根目录双击 `启动月报Demo.cmd`，等到两个服务就绪，打开 http://127.0.0.1:4320/ 。保持启动窗口运行。

1. 点击“用8月演示数据生成”。每次创建独立草稿，不覆盖人工稿，不请求在线数据。
2. 生成成功后点击“进入编辑器”。使用原生 Silex 中文界面；演示草稿含8个基础页面，铜榜超过20行时自动续页，因此当前8月为9页。
3. 双击文字或表格文字修改。选择对象，在右侧调整文字、尺寸、背景等；图片双击打开替换窗口，上传图片保存在项目内。表格选中后有专门工具和行列手柄。
4. 编辑器自动向项目服务保存。关闭前回工作台刷新，确认项目版本已更新。保留失败页面，不要用刷新丢弃未保存内容。版本冲突须读取最新版本合并。
5. 工作台“预览”检查结果；“导出 HTML”下载演示文件，“可编辑项目”下载包含编辑状态的 JSON。普通 HTML 用于查看，JSON 用于恢复编辑。
6. 展开“导入可编辑项目”，选择导出的 JSON，创建独立副本。

## 使用其他月份

本地 AI 通过已配置的 SteamAuto skill 获取标准数据包，在工作台选择相同月份并上传 JSON，然后生成。服务器配置了 generationConfig 时也可以不上传。未配置在线取数时会提示上传，不自动替换成演示月份。

演示数据来自2026-10-15保存的8月上游数据包。历史口径保护仍有效；缺少证据的历史评测和14日指标不会因演示而强行填写。图片和复杂研究文案保留槽位。数据核验不属于本次 Demo 验收。

## 本地 AI 协作

首选[聊天直接修改](CHAT.md)：Codex连接 steam-monthly 后，直接描述页码、选中对象和需求即可修改，网页同步显示，无需先标记或确认提案。下方标记/提案是可选工作方式。

MCP 地址 http://127.0.0.1:4320/mcp 。不支持 HTTP MCP 的终端可用 Node 启动本目录 `mcp-bridge.mjs`，REPORT_SERVICE_URL 指向该地址。启动命令的脚本参数使用本机绝对路径。

编辑器“AI 标记与需求”中标记所选对象并提交。AI 使用 list_ai_requests/get_ai_request 读取需求，再 get_project/propose_object_patch。工作台“AI 修改方案”提供预览与确认应用；发生409重新读取与合并。网页不会因提交标记自行调用模型，需连接并指示本地 AI 处理。

工作台现使用“AI 需求与方案”入口。可查看待处理需求，点击“复制给本地 AI”获得包含服务地址、需求ID和对象ID的指令。AI 提交提案时附 requestId，应用后需求会进入已完成历史。可放弃方案重新处理，或取消需求；这些关闭操作不改变月报内容。过期版本的方案会提示重新生成，不能直接应用。

每张项目卡片支持重命名，名称只用于项目列表，不更改封面或报告标题。导入的新项目自动带“导入副本”后缀。工作台每5秒更新已有项目的服务器保存版本和时间；它表示服务器已收到的版本，不代表编辑器中尚未提交的内容已保存。

## 换机准备

项目目录可以更换，Demo启动器使用相对路径。需要 Node.js 24+、已安装构建的 `work/silex-poc`、安装好依赖的 `pipeline/monthly-service` 和 `releases/monthly-toolkit-portable`。这是开发项目启动方式，并非已打包的免安装应用。在线取数的skill位置与凭据需要在新机器独立配置。

日志在 `work/demo-logs/`。默认仅本机监听，网页服务端口4320，编辑器6805。停止本次启动器只停止它启动的进程，已存在的服务不会主动结束。
