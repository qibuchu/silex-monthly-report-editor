# 大盘页：直接消费SteamAuto结果（2026-10-19）

数据入口为skill的monthly-report命令，对应GET /api/v1/monthly-dashboard/?month=YYYY-MM。默认读取冻结月报包，不使用recompute，不抓网页DOM，不从日序列或原始SQL另算业务指标。尚未将SteamAuto网页页面本身的筛选条件与接口逐项等同；以月报包内定义、月份和窗口为依据。

| 月报对象 | 上游字段 | 月报端操作 |
| --- | --- | --- |
| 月份与截止时间 | report_month、data_cutoff | 日期格式化；截止日不等于指标统计窗口 |
| 上新总量与增速 | kpis.total、kpis.mom_growth | 读取服务端值，数位与百分号格式化 |
| 新品柱图 | market.months[].post_unlock / watching / unknown / release_unlock | 原值作为四个堆叠系列，前三项同色；保留原图例“其他新品数量”，不生成相减得到的“其他”指标 |
| 柱顶总量 | market.months[].total | 直接显示服务端总量；不能以柱段总和反算替换 |
| 日均上新曲线 | market.months[].daily_avg | 直接绘图，不用总量除月份天数 |
| 定级率 | 各月metric_contracts.rated_game_rate | 原值与定义ID校验；不以解锁率替代 |
| 总评测及好评率 | 各月kpis.review_rate_all/sc、经时间验证的market.review_trend | 仅匹配月份和历史证据的数据，不从当前累计数回填 |
| 定级产品评价分布 | market.review_distribution[].rate | 精确匹配原表标签、历史窗口、includes_insufficient=false及定级数分母；直接取rate，不做计数相除或归一化 |

缺失分类时该月份堆叠柱留空，不能把缺失段当作0。日均和总量若分别有效可独立展示；折线遇空值断开，不画成0。坐标轴、堆叠位置、字号和百分比/万单位转换属于显示处理，不是重算业务指标。

历史月份数据通过原始月报包传递到market_history，消费前重新执行时间检查；不再仅凭遗失窗口和状态的旧摘要回填。状态、窗口、快照ID及错误保存在原始文件与独立缺失文档中，不向月报页面插入诊断文案，不改标题、脚注或人工分析。

实现：market-source.cjs、market-details.cjs、generate-draft.cjs、data-quality.cjs及pipeline/monthly-toolkit/run.cjs。生产生成器位于releases/monthly-toolkit-portable，对应脚本与chart.js同步更新；历史0.2.0归档保留原样。

在线获取前执行DataBrain凭据预检；失效即暂停取数及生成，等待用户续期并明确确认。不得用旧包、0值或空榜绕过。上游尚未提供合格字段时，将字段及用途列入独立缺失清单，不在下游重新定义公式。
